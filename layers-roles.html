handler・service・repository の役割分担

商品（product）を例に、各層が「何を知っていて、何をして、何を知らないか」と、それぞれのテストが何を確かめているかを見る。

1. ひとことで言うと、3人とも「翻訳係」

それぞれが、自分の担当する言葉と Go の言葉（domain）の間を訳している

handler

HTTP ⇄ Go の翻訳係

知っているURL、JSON、ステータスコード

知らない業務ルール、SQL、トランザクション

やることJSON・URL を読む／service を呼ぶ／結果やエラーを JSON とステータスにする

判断すること「形」が正しいか（JSON として読めるか、id が数値か）

service

業務の判断と段取り係

知っている業務ルール、どの操作をまとめるか

知らないHTTP、SQL の中身

やること入力が業務的に正しいか確かめる／repository を組み合わせる／BEGIN・COMMIT・ROLLBACK

判断すること「中身」が正しいか（SKU が空でないか、version を送ったか）

repository

SQL ⇄ Go の翻訳係

知っているテーブル、列、SQL、Postgres のエラーコード

知らないHTTP、業務ルール

やることSQL を投げる／行を domain に詰める／DB のエラーを domain のエラーに訳す

判断することDB の結果が何を意味するか（0行なら見つからない、23505 なら重複）

外の世界
JSON・URL・200 / 404
Go の世界（domain）
domain.Product・ErrNotFound
Go の世界（domain）
domain.Product・ErrConflict
DB の世界
行・SQLSTATE 23505・0行

handler と repository は端で「外の言葉」を Go に訳す。service は真ん中で、Go の言葉だけを使って業務の判断をする。だから service は HTTP も SQL も知らずに済む。
